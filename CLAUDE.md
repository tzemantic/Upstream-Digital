# Upstream Digital website

Marketing site for Upstream Digital, a digital marketing agency in Greenwich, CT (paid ads on Meta/Google/LinkedIn, SEO/AEO, web design and development, content, consulting). The live site is currently on Wix Studio at https://www.getupstreamdigital.com/. This repo is a redesign and rebuild of it.

## Layout

- `site/` is the main version: the "reimagined" dark, animated design. Work here by default.
- `archive/faithful-rebuild/` is a responsive, like-for-like rebuild of the current Wix design. Keep for reference; do not edit unless asked.
- `archive/faithful-rebuild/` is a single `index.html` with inline CSS and JS.
- `site/` is plain static HTML with no build step and no dependencies. Fonts load from Google Fonts.
  - `index.html`: the homepage.
  - `services/index.html` and `services/<slug>/index.html`: services hub and one page per service (paid-advertising, seo-aeo, website-design-development, content-creation, digital-marketing-consulting). The homepage service rows link to these.
  - `case-studies/index.html`: the case study hub page.
  - `case-studies/<slug>/index.html`: one page per client (phibro-renewoil, spade-security, olson-floor-supply, italian-consulate-connecticut).
  - `privacy-policy/index.html`: the privacy policy, carried over word for word from the live Wix page.
  - The homepage is kept deliberately light (about 850 words). Service rows are titles only (each links to its service page), the four "Why" cards carry the differentiators without an intro paragraph, testimonials show the pull quote plus the full review (kept long on purpose), and the FAQ covers what visitors ask before hiring an agency that the page doesn't already answer: cost, ad budget, how ad spend is billed, contracts and cancelling, who owns the website and ad accounts, how often clients hear from us, timing, measuring success, switching agencies, kinds of clients, location and AEO. Don't re-add questions the sections above already answer (what services, direct access, how to start). Owner-confirmed policies used in the FAQ: clients own everything built for them, including the website and ad accounts; monthly report plus weekly check-in, tailored to the client; monthly ad budgets from about $500 to several thousand; ad platforms charge the client's own payment method, and Upstream invoices its services separately at the end of each month; cancel at the end of any month, with no strict contracts.
  - Homepage case cards show service tags (`.work-tags`), not stats, because the 36%/96%/25% stats sit in the Results section right above. The hub and case pages still show stats, so don't copy the hub cards onto the homepage.
  - Everything except the homepage is generated by `tools/build-pages.py` (run `python3 tools/build-pages.py site` from the repo root). Edit content in that script, not in the generated HTML, or the next run will overwrite it. The homepage is edited by hand.
  - `assets/styles.css` and `assets/main.js` are shared by every page. They're linked with a version query (`?v=20261115d`) so browsers don't serve stale copies; after changing either file, bump `ASSET_V` in `tools/build-pages.py` and the two links in `site/index.html`, then rebuild. The script checks that each element exists before using it, so homepage-only features (hero canvas, testimonial tabs, marquee, form) are skipped on other pages.
  - Header and footer markup is repeated in every page. Change them in `tools/build-pages.py` (`head()` and `FOOT`) and in `site/index.html`.
  - Paths are root-relative (`/assets/...`, `/#contact`), so the site must be served from the domain root. That's fine on Netlify, Vercel or Cloudflare Pages. A GitHub Pages project subpath would break it.
  - SEO/AEO files: `sitemap.xml`, `robots.txt`, `llms.txt`. Add new pages to all three.

## Brand voice (applies to all copy)

Professional, approachable, confident, down to earth. Conversational and knowledgeable without heavy jargon. No exaggerated claims, no aggressive sales language. The brand promise is: recommend only the services a client actually needs, stay hands-on after launch, give clients direct access to the team, month-to-month with no long-term lock-in.

## Design system for `site/`

Defined as tokens in the `:root` block at the top of the `<style>` in `site/index.html`.

- Colors: abyss `#070D1C` (page), navy `#1D2F4F` (brand navy, raised surfaces), current `#6D94FF` (brand blue, accents and CTAs), sky `#99B9FF` (secondary text on dark), foam `#EEF3FF` (light sections, primary text on dark).
- Type: Montserrat for display and body (Google Fonts, weights 400–800). Headings use light negative tracking (about -.02 to -.04em); keep line-height at .95 or more so the hero lines do not collide.
- Breakpoints: 1100px (burger menu), 980px (tablet layout), 860px, 640px (phone). If you add nav links, re-check the burger breakpoint so the bar never squeezes the logo. Buttons and nav links never wrap (`white-space:nowrap`).
- Idea: noise drifts down the hero, one bright current runs upstream. Sections alternate dark and light.
- On phones the hero fills exactly one screen (`min-height:100svh`, which accounts for the browser's address bar), so the client logo strip appears as soon as the visitor starts scrolling. The phone headline is sized to the screen width (widest line "Break Through" just fits, capped at 60px), and the two hero buttons size to their text and sit side by side (they stack under about 375px).
- Hero animation is a canvas (`#flow`). It pauses off-screen and under `prefers-reduced-motion`.
- Motion system (`assets/main.js`, "Revamp" block; styles in the "Revamp layer" of `assets/styles.css`):
  - Scroll reveal: JS adds `.rv` to common elements and `.in` when they enter view, staggered by `--i`. It only runs when motion is allowed, which adds `.js-motion` to `<html>`. Without JS, or with reduced motion, everything is visible.
  - Header: gains `.scrolled` after 24px and `.hide` when scrolling down past 420px. A `.progress` bar along the top shows how far down the page you are.
  - Process timeline: `--fill` on `.flow` and `.on` on each step, driven by scroll.
  - Counters: `[data-count]` counts up once when it comes into view.
  - Spotlight: `.spot` surfaces get `--mx/--my` from the pointer, on hover devices only.
  - The homepage nav highlights the section in view (`.active`).
- About section: a "What businesses like yours usually need" panel (`#fit`). 27 marketing options (offered tactics mixed with kitchen-sink noise; 8 noise options hide on phones). Conversion tracking is deliberately not listed, because every business needs it. Picking one of ten business types (Title Case labels, ordered roughly from highest-value client to lowest, starting with Medical & Dental; keep the buttons and `FITS` in the same order) lights up 4–5 tactics that type usually starts with; highlighted tactics must always be things Upstream offers. No visible sentence under the options (the owner didn't want to over-explain); a visually hidden live region announces the selection to screen readers, generated from the highlighted keys (`FIT_WORDS` + `FITS` in `assets/main.js`). These are typical starting points, not client results.
- Service pages lead with "What it does for your business": three plain-language outcomes (`outcomes` in `SERVICES` in `tools/build-pages.py`; the `proof` field is kept but not shown, by the owner's choice). The homepage service popups show those same three outcomes; if you change them in the script, update the `<ul>` in each `#svc-panel-N` on the homepage too. Outcomes describe what the service is for; never add numbers or claims that aren't in the case studies.
- Mobile menu (1100px and below): ripples open from the menu button (clip-path circle), with one current flowing up a line beside the links, links rising in one after another, and the in-view section marked with a blue dot. The header pill's glass blur is switched off while open, because `backdrop-filter` would otherwise trap the fixed menu inside the pill. Tapping a section link: the other links fade and the tapped one lights up, the page jumps to the section behind the still-covering menu, then the menu ripples closed to reveal it (`.menu-leaving` / `.picked`). Tap-opens focus the menu itself so no focus box appears; keyboard opens focus the first link. Reduced motion: instant, no movement.
- Services on phones (860px and below): tabs and panels interleave (`display:contents` + `order`) so each service's details open right under it, and the tapped service is held in place on screen when the one above closes.
- Services section: a "confluence" (`#svc-flow`). Five service tabs on the left, SVG tributaries flowing into one detail panel (owner description, three "what's included" points, link to the service page). Click, hover or arrow keys switch; the active line gets a one-time pulse. Lines draw in once on first view and hide below 860px. All five panels are in the HTML (hidden ones toggled) so every service stays crawlable. No 01–05 numbers: services aren't a sequence.
- "What Makes Us Different": heading on one line across the top, four cards in one row below (two-by-two under 1100px, stacked under 640px).
- Homepage FAQ shows the first five questions; the rest are behind a "Show more questions" button (`FAQ_SHOW` in `assets/main.js`). Hidden ones stay in the HTML and the FAQPage data; without JS all show.
- The FAQ heading (`.faq-head`) is sticky beside the questions on desktop, so it stays put as people scroll or open answers; below 980px it stacks and scrolls normally.
- In-page links (nav, footer, "See how it works") land with the section label just under the header: `.band[id]` uses `scroll-margin-top: calc(var(--bar) + 44px - <section top padding>)` and `html` has no scroll-padding. If you give a section different top padding (like `#faq`), give it a matching scroll-margin-top.
- Section kickers are uppercase labels with a leading line. The footer on every page has a large "Get Upstream." link to the contact form.
- Keep the page accessible: visible focus, keyboard-operable tabs and menu, 44px touch targets.

## Accessibility (target: WCAG 2.1 AA)

- Text contrast: brand blue `#6D94FF` is only used for fills, with abyss text on it (6.8:1), never white (2.9:1). Blue text on light sections uses `--ink-blue` `#3558C8` (5.6:1); `.light` and `.cs-main` remap `--current` to it automatically.
- Focus outlines are sky on dark and navy on light sections.
- Moving content: the hero has a Pause/Play button (WCAG 2.2.2) that stops both the canvas and the logo strip, remembered in localStorage `ud_motion_paused`. The logo strip auto-scrolls in JS, but visitors can drag it with the mouse, swipe it, or trackpad-scroll it; it also pauses on hover and focus. Reduced-motion users get no auto-motion at all, and the strip stays manually scrollable.
- Why-us icons are inline SVG line icons in `.quad-icon` tiles (the old `icon-*.webp` files were moved to `archive/unused-assets/`).
- Mobile menu: focus moves into it, stays trapped while open, the rest of the page is `inert`, and Escape returns focus to the menu button.
- Links that open a new tab get hidden "(opens in a new tab)" text from JS. Testimonial tabs support arrow keys plus Home/End. Form errors set `aria-invalid` and point to the status message.
- Before shipping changes, re-check: one h1, no skipped heading levels, every control named, no text under 4.5:1 (3:1 for large text), targets at least 24px, no sideways scroll at 320px.

## Cookie consent

- Branded banner and settings dialog built in `assets/main.js`, modeled on the Usercentrics setup on the live site: Essential (always on), Functional, Analytics, Marketing; Deny / Accept all / Customize; Save settings. A "Cookie settings" button in every footer reopens it.
- The choice is stored in localStorage `ud_consent_v1`. Each page head has a Google Consent Mode v2 snippet that defaults everything optional to denied and applies a stored choice. The banner calls `gtag('consent','update', ...)` and fires a `ud:consent` event.
- When adding GA4/GTM, load it after that head snippet. Anything non-Google (Meta Pixel and so on) must wait for `window.udConsent.marketing` or the `ud:consent` event.

## SEO and AEO conventions

- Every page has a unique `<title>` (aim for 60 characters or fewer), a meta description of 160 characters or fewer, a canonical URL on https://www.getupstreamdigital.com, Open Graph tags and exactly one `h1`.
- Structured data (JSON-LD): the homepage has ProfessionalService, WebSite and FAQPage. The hub has CollectionPage and BreadcrumbList. Each case study has Article, BreadcrumbList and FAQPage. Keep the visible FAQ text and the FAQPage JSON identical.
- Case study pages follow: hero with breadcrumb, h1 and client facts, then stats, then The client / The challenge / What we did / The results / Questions, with a client quote in the sidebar, then more case studies and a CTA. Answer-first writing: lead each section with the direct answer, then detail.

## Content rules

- Copy, client names, testimonials and the three headline stats (36%, 96%, 25%) come from the live site. Do not change, add or invent claims, stats or testimonials. Ask the owner first.
- Client logos link to the clients' own sites.

## Deploying

Hosted on Netlify from the private GitHub repo: every push to `main` publishes `site/` automatically (`netlify.toml`: publish dir, 301 redirects from the old Wix URLs, security headers). No build step. Netlify project: `willowy-creponne-2fb937` (https://willowy-creponne-2fb937.netlify.app), form detection on, Powered-by-Netlify badge off (paid plan). Each publish costs 15 Netlify credits, so batch edits into one push; `netlify.toml` skips publishing when nothing in `site/` or `netlify.toml` changed. Commit and push to publish; the GitHub CLI is at `~/.local/bin/gh` (signed in as tzemantic); the owner wants Claude to publish changes this way. Live since Nov 14, 2026 at https://www.getupstreamdigital.com (www is the primary domain; the bare domain and http 301 to it; Let's Encrypt HTTPS auto-renews). Domain DNS is at GoDaddy (A @ 75.2.60.5, CNAME www to the netlify.app address); never touch its MX/TXT/autodiscover records (Outlook email).
